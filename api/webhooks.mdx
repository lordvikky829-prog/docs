The Google Drive API supports push notifications — sometimes called webhooks — that let your application receive an HTTP POST request whenever a file or folder changes. This is more efficient than polling the API repeatedly.

## How it works

1. Your application registers a **watch channel** on a Drive resource (a file, folder, or the entire file list).
2. Google sends an HTTP `POST` to your registered URL whenever the watched resource changes.
3. Your application processes the notification and responds with `200 OK`.
4. Each watch channel has a configured expiry — you must renew it before it expires.

## Register a watch channel

```
POST https://www.googleapis.com/drive/v3/files/watch
```

### Request body

<ParamField body="id" type="string" required>
  A unique identifier for this channel — generated by your application. Use a UUID.
</ParamField>

<ParamField body="type" type="string" required>
  Must be `"web_hook"`.
</ParamField>

<ParamField body="address" type="string" required>
  The HTTPS URL that Google will send notifications to. Must be publicly accessible and use HTTPS.
</ParamField>

<ParamField body="expiration" type="integer">
  Unix timestamp in milliseconds for when the channel should expire. Maximum is 7 days from now. If omitted, Google uses the maximum expiry.
</ParamField>

### Example request

```bash
curl -X POST \
  "https://www.googleapis.com/drive/v3/files/watch" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "01234567-89ab-cdef-0123-456789abcdef",
    "type": "web_hook",
    "address": "https://yourdomain.com/webhooks/drive",
    "expiration": 1893456000000
  }'
```

### Example response

```json
{
  "kind": "api#channel",
  "id": "01234567-89ab-cdef-0123-456789abcdef",
  "resourceId": "o3hgv1538sdjfh",
  "resourceUri": "https://www.googleapis.com/drive/v3/files?...",
  "expiration": "1893456000000"
}
```

Save the `resourceId` — you need it to stop the channel later.

## Notification payload

When a watched resource changes, Google sends a `POST` to your address with these headers:

| Header | Value |
|---|---|
| `X-Goog-Channel-Id` | The channel `id` you registered |
| `X-Goog-Resource-Id` | The `resourceId` from the watch response |
| `X-Goog-Resource-State` | `sync` (initial), `update`, `add`, `remove`, `trash`, `untrash`, or `change` |
| `X-Goog-Resource-Uri` | The URI of the changed resource |
| `X-Goog-Channel-Expiration` | Expiry time in RFC 2822 format |

The notification body is empty — use the headers to identify what changed, then call the Drive API to fetch the updated resource.

### Example notification handler (Node.js)

```javascript webhook-handler.js
const express = require("express");
const app = express();

app.post("/webhooks/drive", (req, res) => {
  const state = req.headers["x-goog-resource-state"];
  const channelId = req.headers["x-goog-channel-id"];
  const resourceUri = req.headers["x-goog-resource-uri"];

  if (state === "sync") {
    // Initial sync notification — no action needed
    return res.sendStatus(200);
  }

  console.log(`Change detected on channel ${channelId}: ${state}`);
  // Fetch the updated resource using resourceUri...

  res.sendStatus(200);
});

app.listen(3000);
```

<Warning>
  Always respond with `200 OK` within 10 seconds. Google retries notifications that do not receive a timely response, which can result in duplicate deliveries.
</Warning>

## Stop a watch channel

```
POST https://www.googleapis.com/drive/v3/channels/stop
```

### Request body

```json
{
  "id": "01234567-89ab-cdef-0123-456789abcdef",
  "resourceId": "o3hgv1538sdjfh"
}
```

A successful stop returns `204 No Content`.

## Renew a channel before expiry

Watch channels expire after at most 7 days. To continue receiving notifications, create a new watch channel before the existing one expires. Store the expiry timestamp from the registration response and schedule a renewal job accordingly.

<Tip>
  Set a reminder to renew channels at least 1 hour before expiry to avoid gaps in notification delivery.
</Tip>
